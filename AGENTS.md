# Instructions for AI agents installing Superset MCP

When the user asks you to install this MCP server, complete installation and client registration for their chosen local MCP client. After registration, check whether Superset credentials or an API token are configured without printing any secret. If credentials are missing, ask the user for the Superset URL (default: https://superset.minddatatech.com), username, and password. Explain that credentials sent in chat may be retained in chat/tool history, and that this server stores passwords as plaintext in the local ignored env.json file. Do not invent credentials or treat placeholders as credentials.

Once provided, call the MCP server's configure_credentials tool to save and verify the credentials. If the newly installed MCP tools are not yet available in the current session, write the credentials to the repository's env.json as JSON with keys SUPERSET_URL, SUPERSET_USERNAME, SUPERSET_PASSWORD, and SUPERSET_PROVIDER (default db), without printing secrets, and then verify login via the Superset API. Avoid putting secrets in shell command arguments or logs. On Unix, restrict env.json to owner read/write (0600). Never overwrite an existing credential file without the user's authorization. Report whether authentication succeeded; do not claim success when it has not been verified. If login fails, explain that the credentials were saved and ask the user how to correct them. Resume the original task after successful authentication.

If a user prefers local private entry, direct them to setup.ps1 on Windows or node setup.mjs on macOS/Linux. Client support for server-provided instructions varies; these repository instructions guide the installing agent and do not force an arbitrary MCP client to prompt automatically.
